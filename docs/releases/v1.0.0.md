# MnS v1.0.0 non-Substrate baseline — 2026-09-18

## v1.0.0 integration (integration/v1.0.0, 2026-10-05)

The open v1.0.0 work, integrated on one branch per repository and tested
together.

**Images.** Every release image is the candidate the integration e2e flew,
retagged (same digest): `tevv-runtime-host-v1.0.0` and
`tevv-runtime-host-kit-v1.0.0` (TEVV-Airsim dea4290; the kit channel
`tevv-runtime-host-kit-main` points at the same kit), `mns-authoring-v1.0.0`
(built `--kit <that kit> --strict`), `mns-stacks-v1.0.0`
(MnS-Integration-Platform 20b6cec), `tevv-airsim-ros2-bridge-humble-v1.0.0`
(bridge c4086d7) and the dashboard's `-v1.0.0-gb36d1a9` pair; `mns-packs-v1.0.0`
is built from TEVV-Content-Pack-SDK `v1.0.0`, the rc.5 content. The September
baseline's tags were overwritten; their digests remain pullable:
`tevv-runtime-host-v1.0.0` `sha256:303a5c84...`, `mns-authoring-v1.0.0`
`sha256:c91716e1...`, `tevv-airsim-ros2-bridge-humble-v1.0.0` `sha256:b91e4b92...`.

**Packs.** `packs/v1.0.0.lock.json` holds one version per pack: Blocks 1.0.2
(new), Condo 1.0.2, XFS 1.0.2, SAFTI 1.0.4, Warehouse 1.0.1, Office
Environment 1.0.0, Fisherman's Cabin 1.0.1, and the five asset packs
(`mns_vehicle_models` 1.0.4). Older versions are gone from the lock; the
shipped scenarios pin the locked versions, and a test fails when one does not.
All seven levels open in ScenarioLab. SAFTI 1.0.4 no longer carries
ScenarioAuthored content; no shipped scenario used it.

**Spawn starts.** XFS, Condo and Fisherman's Cabin have no floor under the world
origin; `packs/level-spawn-hints.json` names a measured start for each, and
`make fly` / `make campaign` warn about an origin spawn on them.

**Host contract.** `packs/runtime-host-compatibility.v1.json` is copied from the
pinned host image by `tools/images.sh sync`; never edit it by hand.

**Runs end cleanly.** The host image's launcher `exec`s the engine and
`mns-stacks stop` stops the simulator first (`MNS_SIM_STOP_TIMEOUT`), so every
run ends with `run.ended` and a manifest.

**No metrics service in v1.0.0.** Runs write `events.jsonl`, MCAP and a
manifest; scoring them as a service (TEVV-Metrics) arrives in v1.1, which
scores existing runs when it starts.

**Known issues**
- A local `mns-stacks campaign` treats `mission.timeout_s` as a tail after the
  pilot lands; OSMO treats it as a cap. The `vio-osmo-*` and
  `fisheye-surround-shm` specs size it as a cap (300-420 s), so a local run of
  them records minutes at rest and its VIO score is not meaningful. Use
  `vio-reference` locally, or lower `timeout_s`.
- In SHM camera mode the fisheye `camera_info` topics are latched
  (transient-local) and published once; the local recorder misses them, so
  validation skips `intrinsics`. OSMO's recorder records them.
- ScenarioLab opens hand-written specs (inline `vehicles:`) with no drones; it
  reads the folder layout it exports.

## v1.0.0 restructure (release/v1.0.0-next, 2026-09-29)

The baseline below is the tested state the restructure started from
(`v1.0.0-baseline`). The restructure gives every concern one owner (see
MnS-Integration-Platform `docs/v1.0.0-architecture.md`). What changes for you:

**Commands**

| Before | Now |
| --- | --- |
| `./product.sh setup`, `pull-images` | `./setup.sh`, `make pull-images` |
| `./product.sh doctor` | `make doctor` |
| `./product.sh cli runtime ...`, `run-stack`, `status`, `logs`, `stop` | `make fly SCENARIO=<name> [RECORD=1]`, `make stop`, `make stacks ARGS="status|logs ... --stack generated/<name>"` |
| `./product.sh cli campaign ...` (`make campaign`) | `make campaign` (now `mns-stacks campaign`), `make campaign ARGS="..."` |
| `./product.sh start` / `stop` (the launcher's web page on :8760) | gone: use `make dashboard` |
| ScenarioLab only from the dashboard | also `make author [SCENARIO=<name>]` (the same `docker run`) |
| a bag only from the dashboard's Record button | also `make fly ... RECORD=1`; one recorder (`mns-stacks record`), one bag layout |
| `./tools.sh` (airsim-tools) | removed: nothing in the v1 flow used it |
| `tools/offline-export.sh`, `offline-import.sh`, `offline-verify.sh` | removed: they did not work with v1; offline install is a separate feature after v1.0.0 |

**Images** (`images/catalog.yaml`, `images/v1.0.0.generated.env`)

- `mns-product-shell` and `mns-stack-generator` are retired, with
  `MNS_PRODUCT_SHELL_IMAGE` and `MNS_STACK_GENERATOR_IMAGE`. `mns-stacks`
  (`MNS_STACKS_IMAGE`) generates, runs, records and flies campaigns;
  `mns-packs` (`MNS_PACKS_IMAGE`, the content-pack SDK's CLI) installs, stages
  and verifies packs.
- `tevv-runtime-host-kit` (`MNS_RUNTIME_HOST_KIT_IMAGE`) is new: the runtime
  host's companion kit image. It is pinned but never pulled by setup.
  `tools/images.sh verify` warns when the host, kit and authoring image labels
  disagree (one host pin).
- `sim-real-eval-worker` and `airsim-qgc-x11` are pinned on immutable
  `-v1.0.0` tags: `sim-real-eval-worker-v1.0.0` retags the accepted
  `sim-real-eval-worker-v1.0.0-rc` build and `airsim-qgc-x11-v1.0.0` retags
  `airsim-qgc-x11-latest`, both at the digests they were already pinned to
  (`sha256:9780594b…` and `sha256:fe1e9e05…`), so the bits generated stacks run
  are unchanged.
- `tools/images.sh verify --release` holds every image the release ships to a
  release tag and a digest: the channel's variables, the pack lock's pins and
  every image set row (what generated stacks run), not only the channel's own
  images.
- A `.env` image line (`MNS_STACKS_IMAGE=mns-stacks:local-test`) overrides a pin
  for the dashboard and every headless target; each prints a note.

**Packs**

- Every pack operation goes through `mns-packs`. Staging for ScenarioLab is
  `mns-packs stage-authoring --lock packs/v1.0.0.lock.json`: the lock decides
  each pack's version, so a store holding `mns_vehicle_models` 1.0.3 and 1.0.4
  stages only 1.0.4 (the fix for "asset pack definition identity is invalid or
  duplicated"). `make dashboard` and `./download-packs.sh` bring installed packs
  to the lock's versions first (`--sync`).
- The lock's `required_images` are now `packs`, `stacks`, `authoring`,
  `runtime_host` and `ros2_bridge`.

Nothing to migrate on disk: `scenarios/`, `generated/`, `runs/` and
`.mns/v1/` keep their layout.

## Camera and iceoryx

The packaging dependency guard preserves the iceoryx2 v0.8.1 build fix. The final native runtime additionally retains view state for RGB scene captures and selects the project's GI/reflection methods, allowing Warehouse indirect lighting into the fisheye capture. This does not change segmentation captures or the shared-memory transport.

The final runtime delivered 242 valid 640x480 BGRA8 raw camera messages in 30 seconds (145 distinct timestamps), 698 cadence messages and 6001 IMU messages. Logs confirm successful iceoryx publishes with a recipient. No RPC camera bypass was used. See `lighting-frames.json`, `lighting-runtime.log` and `lighting-camera.jpg`.

The Warehouse viewport renders clearly. The final fisheye image shows the shelves, floor and roof, but some patterned roof/wrapped surfaces remain. This baseline fixes loading, image publication and dark scene-capture lighting; it does not claim artifact-free rendering or validate every other pack.
