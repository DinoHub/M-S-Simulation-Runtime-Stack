## What changed for the product

- Channel `v1` is the default (`make dashboard`, `./product.sh`, dashboard compose defaults).
- Pack mount directory `MNS_PACKS_DIR` (default `.mns/v1/packs`) + `tools/pull-packs.sh`
  (`--list-remote`, `--release-tag`, `--import`); split releases are reassembled.
- Pack payloads are hard-linked from the PackStore into ScenarioLab staging and generated
  stacks instead of copied (12 GB per stack before).
- The authoring image bakes exactly one pack, `mns_vehicle_models`; no level pack is baked.

## Acceptance

Isolated dashboard candidate (compose project `mns-v1-accept`, channel `v1`, production images) on 2026-09-18, evidence under `~/TestStandalone/mns-v1.0.0/evidence/live/`:

- Installed the seven pack releases through the channel lock into `.mns/v1/pack-store` (sha256 + `packs verify` by the v1.0.0 shell); preflight: docker, authoring/generator images, pack_store (6 level + 1 asset), packs_staged for the frozen capability, display, xauthority all `ok`. Staged payloads are hard links of the store blobs (link count 7-9 on the shared inodes).

- PX4 stack (runtime host, px4, bridge all v1.0.0, generated via `POST /api/scenario/generate` + `/stacks/…/up`): `MNS_SCENARIO_ORIGIN_READY (81200,-14800,2500) yaw 90`, `MNS_VEHICLE_SPAWN Copter1 world_cm=(81557.9,-14756,2600) yaw 78.312 scenario_api_ned_m=(3.579,0.44,-1)`, teleop available on `udpout:127.0.0.1:14560`. A first attempt 35 s after spawn was refused to arm (`Preflight Fail: ekf2 missing data`); the retry ~3 min after launch flew.
- ArduPilot stack (ardupilot-v1.0.0, from-source SITL): identical origin/spawn lines; C2 `udpin:127.0.0.1:14552`; ARM + TAKEOFF acked, climb to z −0.44 (≈5 m), forward ≈8 m, back, descent, touchdown (landed_state 0). 444 metrics events. ## Known open findings

Carried from the 2026-09-10 acceptance, observed again or not exercised, none regressed by this release:
- ROS `map->odom` is the authored spawn offset, so ROS map z is off by the pre-arm settle drop (~4.58 m on Electric Dreams). Owner: TEVV-Airsim-ROS2-Bridge.
- ScenarioManager's Start-anchor log reports the level's first PlayerStart, not the vehicle spawn (reporting only). Owner: TEVV-Airsim.
- ArduPilot's dedicated C2 serial carries heartbeats only; the vehicle stays armed after the velocity-descent "land". Owner: TEVV-Ardupilot / dashboard pilot backend.
- PX4 arming right after spawn is refused until EKF2 has data (~1-2 min); the dashboard teleop client arms immediately on session start.
- Mission-recording DB persistence and the Kafka/ClickHouse metrics archive were not exercised (`metrics_archive.loaded=false`, no kafka bridge in the candidate).
- The producer now tags one PlayerStart `MnSScenarioOrigin` per level; the untracked Condo/xfs/Pendleton/safti project copies carry that edit only on the build host (their content is not in git).
